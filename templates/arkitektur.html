Slik henger systemet sammen — ledd for ledd

Ærlig gjennomgang av hva som faktisk skjer fra en samtale tas opp til innsikten lander hos en saksbehandler. Ingenting er skjult: hvert ledd kjører et sted og krever noe.

⚠️ Dette er ikke plug-and-play. Et "ferdig produkt" er egentlig en kjede av integrasjoner: lyden må hentes ut av telefonisystemet, transkriberes, analyseres, lagres og kobles tilbake til kundens systemer. Hvert ledd kan kjøres i sky (enkelt, fast kostnad) eller selvhostet (kompleks, men full kontroll). Det tar tid å forstå hvordan delene snakker sammen — derfor denne siden.
✅ Ærlig anbefaling for å komme i gang: start i sky (Azure, EU-region). Forutsigbar månedlig kostnad, ingen egen hardware/drift, raskest til pilot, og trygt nok for sensitive data (EU + databehandleravtale). Selvhostet NB-Whisper er en SENERE optimalisering — den kutter per-minutt-kostnad ved stort volum og gir maks personvern, men da må dere drifte en modell-server (GPU, oppdatering, oppetid). Ikke start der.
📞 Opptak→ 🎙️ STT→ 🧠 Analyse→ 💾 Lagring→ 📊 Dashboard→ 🔁 CRM
1📞 Telefoni / opptak — hvor lyden kommer fra
Kjører hos: telefonileverandøren (Loyalty bruker f.eks. Puzzel eller Genesys).
Krav: tilgang til deres API / webhook / opptakslager for å HENTE UT lyden.

Samtalene skjer i Loyaltys contact-center-plattform. Lyden må hentes ut derfra før vi kan gjøre noe. Dette er ofte den vanskeligste delen — den avhenger helt av hvilken plattform de bruker, og må avklares med Loyalty/leverandøren. Det er ikke noe vi styrer alene.

2🎙️ STT — tale blir til tekst
Lyden transkriberes, helst med taler-separasjon (hvem er agent, hvem er kunde).
Sky (enkelt) — Azure AI Speech Send lyd til et API → få tekst. Krav: Azure-konto + nøkkel. ~1 kr/lydtime (forutsigbar opex). EU-region. Oppe på minutter.
Selvhostet (komplekst) — NB-Whisper Du KJØRER modellen selv. Krav: server med GPU (8–24 GB VRAM for fart; CPU tar ~1,5 min på en kort klipp), Python + PyTorch + transformers (~GB), modell-nedlasting, og 24/7-drift + patching. Ingen per-minutt-kost, men du drifter ML-infra.

Ærlig: «STT_BACKEND=nb-whisper» i demoen er bare en peker. I produksjon må den modell-serveren faktisk stå og kjøre et sted — egen GPU-maskin ELLER en GPU-VM i Azure som dere drifter (ikke Azure-managed).

3🧠 Analyse — tekst blir til innsikt
Transkriptet analyseres → QA-scorecard, sammendrag, sentiment, churn, compliance-flagg.
Sky (enkelt) Azure OpenAI (EU) eller Claude/OpenAI-API. API-kall + nøkkel, per-token-kostnad. Sterkest kvalitet.
Selvhostet (komplekst) Lokal LLM (Ollama) på GPU — samme drifts-byrde som STT. ELLER regelbasert (demoens «mock»: gratis, men ikke ekte AI — god nok til pilot).
4💾 Lagring
Kjører: database (+ fil-lagring) lokalt ELLER i Azure (Postgres + Blob).

Transkript + analyse må lagres. Her gjelder personvern fullt ut: kryptering, tilgangsstyring, sletteregler, databehandleravtale. Demoen forenkler dette (ingen ekte database ennå) — en produksjonsløsning trenger sikker lagring.

5📊 Applikasjon / dashboard
Kjører: en web-server — lokalt ELLER Azure (Container Apps / App Service).

Selve web-appen (denne demoen) som viser samtaler, dashboard og rapporter. Lettest å hoste i sky.

6🔁 Integrasjon tilbake til Loyaltys systemer
Krav: integrasjon mot deres CRM / QA-verktøy / rapporter.

Resultatene må inn der agentene og lederne faktisk jobber. Mer integrasjonsarbeid, avhenger av deres interne stack. Det er dette som gjør det til en kjede, ikke én knapp.

Oppsummert valg: Vil dere bare i gang med forutsigbar kostnad og minimal drift → sky (Azure EU). Tenker dere langsiktig kostnad/personvern ved stort volum → selvhostet senere (med drift av modell-server). Bruk 🧭 Veiviseren til å se hva ditt konkrete svar gir, ledd for ledd.
